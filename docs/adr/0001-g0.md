# Decision: G0 overlap and feasibility

- **Status:** Accepted (narrow)
- **Date:** 2026-11-06
- **Deciders:** Sankaranainar Parmasivan
- **Inputs:** [gap-matrix.md](../g0/gap-matrix.md), [framework-matrix.md](../g0/framework-matrix.md), gate G0 in
  [../design.md](../design.md)

## Question

Gate G0 asks whether to build spanslo as a new project. It passes if the hands-on check confirms
that agent-sre, Tumult and DeepAgentLabs agentic-chaos do not compute injector-independent SLIs
and windowed budgets from `gen_ai.*` spans, that ResiliBench does not already answer the fault
position and recovery cost questions, and that the name is free. If it fails, the design says to
contribute the scorer to an existing project instead.

## Evidence summary

### From the gap matrix (week 1, four tools run against one toy agent)

- **No tool derives SLIs from `gen_ai.*` spans.** agent-sre 3.7.0 has SLOs, error budgets and burn
  rates, but they are fed by booleans the caller records; it has no span ingest and re-exports
  attributes under `agent.sre.custom.*`. Tumult 2.22.0 defines `gen_ai.*` constants, but the spans
  captured over OTLP carried `resilience.*` and `tumult.*` attributes only. DeepAgentLabs
  agentic-chaos 1.0.0 has no OpenTelemetry code. agentic-chaos-security 1.0.0 emits `chaos.*`
  spans.
- **Budgets:** only agent-sre has them. They use wall-clock windows with a single burn-rate
  window; there are no run-count windows and no multiwindow pairs.
- **Recovery is surface-level in the tools that measure it.** DeepAgentLabs scored 100 on a run
  whose task failed (the agent caught a model error and stopped; its rule treats "nothing escaped,
  not retried" as recovered). agent-sre's resilience score ignores the recovery time and cost
  inputs it accepts. agentic-chaos-security can check task output through a user-written probe,
  but has no recovery-point or cost measure.
- **Fault records carry no turn or run id.** None of the four attaches either; agentic-chaos-security
  native events also have no timestamp. Correlation needs adapter work, as the design assumes.
- **ResiliBench** (paper pages 1 to 5, poster, abstract): probabilistic tool failures (base
  success 0.8), a three-level outcome (full, partial, failure), a 10-turn limit, and the gap
  between optimal and flawed workflow prompts. As read, it does not control fault position and
  has no recovery cost, OpenTelemetry or SLO component.

### From the framework matrix (week 2, LangGraph, OpenAI Agents SDK, smolagents)

- **None of the three frameworks emits OpenTelemetry on its own.** What appears depends on the
  instrumentor chosen. Only OpenLLMetry (LangChain, Agents SDK, OpenAI client), the OpenTelemetry
  contrib OpenAI instrumentor and LangSmith's OTel mode emit `gen_ai.*`. OpenInference emits none.
- **Turn index t can be rebuilt from spans alone** (rank of model spans by start time) whenever
  the model call is instrumented; the span count matched the real request count in every run
  where model calls were instrumented.
- **Step index i needs agent-level or tool-level spans with a tool name and arguments.** It
  rebuilt correctly for OpenLLMetry LangChain, OpenInference LangChain, both Agents SDK
  instrumentors and OpenInference smolagents (after excluding smolagents' `final_answer`). It
  cannot be rebuilt from OpenAI-client instrumentors (no tool spans) or MCP-client instrumentors
  (no model spans). Argument attributes match the wire arguments only for the Agents SDK
  instrumentors. Each turn made one tool call, so the argument-hash tie-break was not tested.
- **MCP trace context travels only in `params._meta`,** on both stdio and Streamable HTTP. No HTTP
  `traceparent` or `baggage` header and no environment variable was seen. MCP SDK 2.3.0 injects
  `traceparent` and `baggage` natively; SDK 1.30.0 injects nothing, and an instrumentor is needed.
  OpenLLMetry's MCP instrumentor failed to load under SDK 2.3.0.
- **Ecosystem friction:** smolagents' MCP adapter did not import under MCP SDK 2.3.0 and needed
  a pin below 2; the contrib OpenAI instrumentor needed a pinned `opentelemetry-util-genai` and an
  undeclared `httpx`.

### G0 exit criteria

| Criterion | State |
| --- | --- |
| Every tool ran at least once | Met for the four tools; Tumult `run-live` was not run (needs Claude Code and credentials) |
| agent-sre does not compute span-derived SLIs and windowed budgets | Supported by the runs and source; budgets exist but are caller-fed |
| Tumult does not | Supported on the paths that could be run; `run-live` is the one unobserved path |
| DeepAgentLabs agentic-chaos does not | Supported; project moves fast (three releases in three days before 1.0.0) |
| ResiliBench does not answer fault position and recovery cost | Provisionally supported; appendices B.3 and B.4 unread |
| Name free on github.com, pypi.org, pkg.go.dev | Met: checked 2026-11-07; only this repo on GitHub, PyPI and npm return 404, Go path is unique |

## Recommendation: narrow

Proceed with the project, with a narrower scope than the design states.

### Reasons

1. **The gap is real where the design placed it.** No tool turns spans into SLIs, task-verified
   recovery or run-count budgets, and the one concrete mismatch observed (score 100 on a failed
   task) is the problem the design's two recovery levels address. This argues against stopping.
2. **The design assumes more from framework spans than the evidence supports.** It treats
   `gen_ai.*` spans from the frameworks as a given input. In practice the span content depends on
   which instrumentor is installed, one of the three main instrumentors uses a different
   vocabulary, and `i` needs a combination of instrumentors that was not tested. This argues
   against proceeding exactly as designed.
3. **Gate items remain open.** The ResiliBench appendices and the name check are not done, and
   `run-live` was not observed. A full go would be premature.
4. **Several inputs move quickly** (agentic-chaos releases, instrumentor and MCP SDK versions), so
   commitments that depend on third-party behavior carry cost.

### What narrows

- **Scorer input contract.** For the benchmark, rely on spans the harness controls (the model
  wrapper and tool hooks already in the design) for turn and tool identity. Treat third-party
  framework instrumentation as a compatibility target tested on recorded fixtures (the runs in
  `~/scratch/g1/out/runs/`), not as a guarantee.
- **Trace context and baggage are optional.** Do not depend on them for turn numbers. They are
  present only with MCP SDK 2.x or an instrumentor, and only in `_meta`. The design's cross check
  stays as written ("where the client forwards it").
- **External injector adapters stay optional** and are built from recorded real output per source,
  without a promise of live correlation, since no source records a run id or turn.
- **Framework order.** Start with the Agents SDK (native `_meta` propagation, clean tool
  arguments), then LangGraph, then smolagents (MCP SDK pin, `final_answer` exclusion). Revisit
  at G1 whether all three are kept.
- **Positioning.** Present the contribution as span-derived SLIs, recovery levels and run-count
  budgets that feed an agent-sre-shaped report, not as a competing budget system.

### What would change this

- **Toward contributing instead (stop):** the ResiliBench appendices or code show a fault position
  or recovery cost analysis; or agent-sre or Tumult adds span ingest with recovery levels and
  budgets (including a `run-live` run showing `gen_ai.*` spans plus budgets).
- **Toward the full design (go):** the open items below close without a conflict, and a
  two-instrumentor combination reproduces `t` and `i` on the three frameworks.

## Semconv mapping risks

The GenAI conventions are at Development status and `spec/semconv-mapping.yaml` is meant to absorb
that. The runs show specific variation the mapping must handle:

1. **Same concept, different attribute names.** LangSmith's OTel mode emits `gen_ai.system`;
   OpenLLMetry and contrib emit `gen_ai.provider.name`. LangSmith also emits legacy
   `gen_ai.prompt` and `gen_ai.completion`.
2. **`gen_ai.operation.name` values outside the design's list** (`chat`, `invoke_agent`,
   `execute_tool`, `plan`): OpenLLMetry LangChain emits `create_agent` and `execute_task`;
   LangSmith emits `chain`.
3. **Provider value describes the SDK, not the backend.** Contrib reported `openai` while the
   model was served by Ollama; LangSmith reported `qwen` for the system.
4. **A second vocabulary.** OpenInference uses `openinference.span.kind`, `llm.*`, `input.value`,
   `tool.*`. Supporting it means a second mapping, not a renamed attribute.
5. **Token attributes are not uniform.** OpenLLMetry's Agents SDK spans carried no
   `gen_ai.usage.*`; token SLIs (Token Amplification Factor, recovery tokens) would need the
   model-call spans.
6. **Tool arguments are wrapped or reformatted** by three of the four agent-level instrumentors,
   so a canonical-JSON hash needs per-source unwrapping.
7. **Content is off by default** in the contrib instrumentor; nothing here relies on content, but
   oracle-related checks that read messages would.
8. **MCP spans.** From reading the MCP SDK 2.x source (not observed, because the server process did
   not export spans), server spans set `gen_ai.operation.name = execute_tool`. If both client and
   server spans reach the scorer, tool calls could be counted twice.
9. **Version coupling.** The pin must cover instrumentors and the MCP SDK, not only the
   conventions release: the contrib instrumentor and `util-genai` were incompatible at the latest
   versions, and an MCP SDK major version broke two adapters.
10. **Stacked instrumentors** (for example a framework instrumentor plus an OpenAI-client
    instrumentor) were not run; duplicate model spans would break the rank rule for `t`.

## Open items

- ResiliBench appendices B.3 (simulator) and B.4 (scoring), and the repository's task and tool
  JSON, which were not in the shallow clone; the repository has no license file.
- Name availability for spanslo on github.com, pypi.org and pkg.go.dev.
- Tumult `run-live`: whether it emits `gen_ai.*` spans (needs Claude Code and credentials).
- Which semantic-conventions-genai release to pin in week 3.
- Parallel tool calls, streaming model responses, stacked instrumentors, and faulted runs: all
  untested here.
- Repetition: each matrix cell is one run.
- Whether any run contacted external hosts: no keys were set and no errors appeared, but network
  traffic was not captured.

## Alternatives considered

- **Go as designed.** Not recommended yet, for the reasons under "Recommendation".
- **Stop and contribute to an existing project.** The evidence does not show an existing project
  filling the gap, so this is held as the fallback if an open item turns up an overlap.
